# ДЗ 3. Интерактивная коллекция

## Задача

Превратите готовую статическую страницу в интерактивную коллекцию на JavaScript.

Пользователь должен уметь:

1. выбрать карточку и увидеть подробности;
2. отфильтровать карточки по категории;
3. увидеть количество карточек после фильтрации;
4. получить случайный вариант из видимых карточек;
5. вернуть страницу в исходное состояние.

Основное время должно уйти на JavaScript, проверку поведения и исправление ошибок. Отдельные ТЗ и отчеты писать не нужно.

## Этап 1. Наполните коллекцию

В `project/index.html`:

- замените заголовок и описание страницы;
- добавьте минимум шесть содержательных карточек;
- используйте минимум три категории;
- настройте у каждой карточки `data-title`, `data-description` и `data-category`;
- настройте кнопки фильтров через `data-filter`;
- удалите демонстрационные тексты стартового проекта.

Значения `data-category` у карточек должны совпадать со значениями `data-filter` у кнопок.

Проверка: у каждой категории есть минимум одна карточка, а данные карточек отличаются друг от друга.

Рекомендуемый коммит:

```text
content: наполнить коллекцию своими данными
```

## Этап 2. Реализуйте выбор карточки

После клика по любой карточке:

- в панели отображаются ее название и описание;
- прежнее выделение снимается;
- новая карточка получает класс `collection-card--selected`;
- у карточек корректно обновляется `aria-pressed`;
- панель получает класс `details-panel--pulse`, запускающий CSS-анимацию.

Используйте одну общую функцию выбора. Не создавайте отдельную функцию и отдельный текст для каждой карточки.

Проверка: выберите A → B → A. Выделена только последняя карточка, а панель показывает соответствующие ей данные.

Рекомендуемый коммит:

```text
feat: реализовать выбор карточки
```

## Этап 3. Добавьте фильтрацию

После нажатия кнопки категории:

- активна только одна кнопка фильтра;
- она получает класс `filter-button--active`;
- у кнопок корректно обновляется `aria-pressed`;
- неподходящие карточки получают класс `collection-card--hidden`;
- фильтр «Все» показывает всю коллекцию;
- `#visible-count` содержит количество видимых карточек.

Если новый фильтр скрыл выбранную карточку, выделение снимается, а панель возвращается к начальному состоянию.

Проверка: выберите карточку категории A, затем включите категорию B. Карточка A скрыта, выбор сброшен, счетчик верен.

Рекомендуемый коммит:

```text
feat: добавить фильтры и счетчик
```

## Этап 4. Добавьте случайный выбор

Кнопка «Случайный выбор» должна:

- выбирать только среди видимых карточек;
- не выбирать текущую карточку повторно, если доступна другая;
- использовать ту же функцию выбора, что и обычный клик;
- корректно работать после смены фильтра.

Не создавайте второй независимый сценарий обновления панели.

Проверка: включите категорию с двумя карточками, выберите одну и несколько раз используйте случайный выбор. Скрытая категория не должна появляться.

Рекомендуемый коммит:

```text
feat: добавить случайный выбор
```

## Этап 5. Реализуйте полный сброс

Кнопка «Сбросить» должна:

- активировать фильтр «Все»;
- показать все карточки;
- снять выбранное состояние;
- вернуть исходный заголовок и описание панели;
- восстановить правильный счетчик.

Проверка: фильтр → выбор карточки → случайный выбор → сброс. После сброса интерфейс выглядит и работает как после первой загрузки.

Рекомендуемый коммит:

```text
feat: реализовать полный сброс
```

## Этап 6. Настройте анимацию и проверьте страницу

В `styles.css` уже есть класс `details-panel--pulse` и анимация `panel-pulse`.

- измените минимум два параметра подготовленной анимации или создайте собственную;
- запускайте ее добавлением CSS-класса из JavaScript;
- сохраните правило `prefers-reduced-motion`;
- проверьте кнопки через `Tab`, `Enter` и пробел;
- проверьте отсутствие красных ошибок в Console;
- проверьте локальную и опубликованную версии.

Дополнительно добавьте новую карточку только в HTML и убедитесь, что выбор, фильтр и счетчик работают без отдельного обработчика для нее.

Рекомендуемый коммит:

```text
style: настроить анимацию и состояния интерфейса
```

## Штрафы

Штрафы суммируются, но итоговая оценка не может быть ниже 0.

- **−1 балл**, если сайт не опубликован на GitHub Pages либо опубликованная версия не соответствует `master`.
- **−0,5 балла**, если в работе остались демонстрационные карточки, категории или тексты стартового проекта.

## Когда за работу ставится 0 баллов

- Работа не сдана до дедлайна.
- Обнаружены признаки чужого кода, чужого текста или результата, созданного нейросетью и выданного за собственный.
- Студент не может ответить на вопросы по своему коду или решениям.
- Студент не может выполнить небольшое изменение кода во время проверки.
- Итоговый чек-лист не заполнен полностью.
- Хотя бы один pull request по работе не замержен к моменту сдачи.
- Сдан почти неизмененный стартовый проект или работа без основного JavaScript-поведения.
- Проект не открывается, и проверить результат по репозиторию и GitHub Pages невозможно.

Частично выполненная самостоятельная работа оценивается по критериям. Неполный объем сам по себе не является основанием для 0 баллов.

## Использование ИИ

ИИ можно использовать как консультанта, но не как автора работы.

Можно:

- попросить объяснить один метод или ошибку из Console;
- получить наводящую подсказку по текущему этапу;
- проверить собственное понимание функции;
- предложить тесты для уже написанного кода;
- сверить готовую работу с критериями.

Нельзя:

- просить написать готовый `script.js` или выполнить этап целиком;
- вставлять сгенерированный код, который вы не писали и не понимаете;
- поручать ИИ описание PR или заполнение чек-листа;
- скрывать использование ИИ.

В описании PR достаточно честно написать, какой инструмент использовался и с чем он помог. Отдельный отчет об ИИ не нужен.

Самостоятельность проверяется не стилем текста, а объяснением кода и небольшим изменением по новому условию. Преподаватель может попросить добавить карточку, изменить категорию, поправить сброс, изменить анимацию или найти ошибку в селекторе.
